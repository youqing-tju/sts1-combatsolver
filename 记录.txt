STS1 CombatSolver 工程经验记录
更新时间：2026-11-01（严格蓝本纠偏版）

🔴 最新最高规则：禁止自创，一切以蓝本为标准复刻；蓝本没有 = 不做。
此前“项目自定义/本地扩展/用户规则/UI 适配可保留”的口径全部废止。本文与蓝本冲突的旧经验以
`docs/plans/2026-11-01-strict-blueprint-parity.md` 为准，已在对应条目就地纠正。

一、协作与执行

1. 已确定目标内不要事事请示。代码、测试、诊断、构建、安装、真机验证和本地 commit 应自主完成，事后用短报告交代改动、证据、风险和回退。只有产品语义存在不兼容取舍、不可逆或外部操作、必须违反硬规则时才询问。请示不算进度。
2. 自主执行不等于降低证据标准。可以边查边改，但不能把“合理推测”写成“根因已闭环”，也不能把“测试全绿”写成“真机验收完成”。
3. 计划是实施起点，不是限制调查与修复的笼子。发现计划假设错误时，先核实事实，再修正计划并记录偏差；不要为了严格照计划而保留已知错误。
4. 不自行 push，不为了缩短耗时砍搜索预算、宽度、深度或关闭机制。项目评价标准是牌打得更好，而不是毫秒数更少。

二、蓝本复刻与需求边界

5. “蓝本已有”必须能定位到源码。找不到就明确写“蓝本没有”，不能凭方法名或印象补出一个 ApplyRoute 之类的伪依据。
6. 蓝本三个 StrategyPanel 是会改变搜索行为的控制器；只读状态区只是 STS1 当前状态展示适配，不能宣称完成控制器 parity。
7. AdoptRoute、ApplyCurrentTurn、RouteFrozen 是不同概念。蓝本按当前回合部署，后续回合在精确 continuation 命中时可复用；不能笼统描述为“冻结整条路线”或“每回合必定从头重搜”。
8. 蓝本没有的功能不再“标注后保留”，而是一律不做/撤销。例如“点击路线行，AUTO 到目标回合末”不是蓝本复刻，按最新规则删除。

三、测试、真机与根因闭环

9. 单元测试、构建、真机验证是三层不同证据。547 条测试全绿只证明自动化覆盖的行为通过，不证明 UI 点击、真机回合推进和原生触发链正确。
10. 修复报告建议分四栏：已证实事实、当前假设、已实施改动、仍缺验证。候选修复在真机通过前保持“候选”状态。
11. 探针结论不能超出探针实际观测。队列非空时 endTurn() 尚未启动，不等于它永远不会启动；探针已观测到入口启动，就不能再把“入口完全没启动”当根因。
12. 临时诊断探针只保留到问题闭环。结束验证后删除或明确关闭，避免高频日志和永久诊断代码污染执行路径。

四、UI 与执行架构

13. 完整路线预览与执行队列必须分离。RoutePreview 保存完整步骤、绝对回合和 END_TURN 边界；ArrayDeque<RouteStep> 只负责消费下一手。否则每出一牌，后续回合号都会被重新编号。
14. 布局、绘制和点击命中应共用同一份行缓存，避免“看得见却点不中”；但蓝本没有的点击行为本身不得自造。
15. 【旧有界 AUTO 规则废止】蓝本没有“点 Tn 打到回合末”，不得继续保留 BoundedAutoTarget。
16. 路线生命周期只按蓝本 retained route / continuation / frozen 各自语义实现，不自造停止目标或冻结模式。
17. 渲染只读缓存，不在渲染路径调用 SimState.capture()。capture 只在主线程回合边界或动作稳定后进行，真机对象不得进入后台搜索线程。
18. 被动药水不能套用主动药水的 HP 使用门槛；空槽 PotionSlot 也不能显示成真实药水。UI 只展示确实可访问的数据，不伪造搜索内部遥测。

五、原生回合末调用链

19. AUTO 只设置 player.endTurnQueued 与手点 EndTurnButton.disable(true) 不等价。后者还包含 NewQueueCardAction、releaseCard() 等原生步骤，因此改走 disable(true) 是合理的候选修复方向。
20. 回合末遗物、Power 和手牌效果集中在 GameActionManager.callEndOfTurnActions()，其调用与 cardQueue 中 card == null 的哨兵项相关。不能用 actionManager.endTurn() 代替完整原生路径，否则会跳过玩家侧流程和敌方阶段。
21. 截至本记录时，disable(true) 候选修复尚未完成真机闭环。灼烧、多层护甲、金属化、奥利哈刚及敌方阶段仍需逐项验证；不得提前记为已修复。

六、搜索与镜像调试顺序

22. 先修验收数据管线，再调搜索策略。对拍出现 previous still pending 时，后续失配可能被前一条污染；应先解决对拍队列积压，再用数据判断搜索优劣。
23. “节点预算 50 万但只用 0%～10%”说明瓶颈不是预算不足。应检查 open 表为何提前耗尽：剪枝、去重/转置表、每动作展开数、回合层 horizon，而不是继续盲目加预算。
24. 能力牌长期排在后续回合且每回合重算，可能形成永远轮不到的结构问题。Feel No Pain 的案例要与浅搜索一起分析，不应只针对单卡加特例。
25. 数据干净度小修应直接 TDD：Coverage 白名单补充 Lantern、NeowsBlessing、Pear；SimState.capture() 将 PotionSlot 空槽映射为 null；Burn+、Decay+ 回合末数值读取 upgraded 状态，不能写死未升级常量。
26. 游戏语义必须用 javap 和原版 localization 核实。升级数值查 upgrade()/UPGRADE_DESCRIPTION，卡牌 ID、Power ID 和药水 ID 不凭记忆。

七、提交与交接

27. 每个逻辑改动独立 commit，保证可单独 revert。文档状态必须跟随真实证据更新，未完成真机验收的项目保持未完成。
28. 交接文档记录当前 HEAD、测试实数、真机覆盖数、未解决风险和下一步；长期记忆只保留稳定规则，具体进度以 docs/handoff-prompt.md 为准。

八、跨回合续跑（Continuation）实现经验（2026-11-01）

29. 精确状态戳不能用哈希，也不能复用剪枝用 fingerprint()。蓝本分别有 CaptureLive 与 CapturePredicted 两条归一化路径；可共享低级 append helper，但不能自造单一 from() 代替两侧语义。
30. 戳按“字段路径=值”逐条展开，差异诊断定位到具体牌堆下标、怪物子字段和 RNG 子字段；只报“牌堆不一样”等于没报。
31. 【纠正旧规则】蓝本 hand/draw/discard/exhaust 四个牌堆全部按列表原顺序编码；手牌不得排序成无序多重集。Power 等顺序也按蓝本 append 路径，不自行重排。
32. 最终 best 只用于选择稳定边界；随后必须按蓝本回放最终路线，在预期 action/turn 调 CapturePredicted。不得用节点链已有 state 代替回放，也不能从后处理前的旧候选摘边界。
33. 边界资格是四个合取：END_TURN 跨回合、玩家没死、敌人没全灭、后面确有动作。末尾终局/死亡/胜利一律不缓存，否则会把“已经结束的战斗”当成还能续跑。
34. 命中要保留完整 preview（含已走过的回合），只裁执行队列。裁错一格就会把上一回合的 END_TURN 再执行一遍。
35. miss 必须分四种归因，且“手工分歧”优先于“状态不一致”。手工打了一张牌必然也让状态对不上，报成 state_mismatch 会把人引去查镜像。
36. 判定“这是不是手工输入”用“被观察到的出牌不是我刚排队的那张对象”。覆盖手工点牌，也覆盖遗物/药水的自动出牌；代价是后者会被归成 manual_divergence，处置相同（都重搜），可接受。
37. 【旧有界 AUTO 规则废止】续跑只遵循蓝本 AutoTurnStart 精确校验与部署状态机，不叠加本地 targetTurn/冻结诊断机制。
38. 续跑最可能踩的坑是“戳里包含了预测不准的字段”（未镜像怪物的意图、召唤物卡面伤害、一次性遗物 counter）。若真机持续 state_mismatch，按 first_difference 去修模型；删字段凑命中率等于放弃校验。

九、药水策略（D5）实现经验

39. 策略要能在“最底层拦截”+“最终答案复核”两处同时生效。只在最终比一下分数，落后通道（novelty/portfolio/补搜）会把违禁药水捞回来；只在展开处拦，Force 又永远满足不了。
40. Force 是硬约束不是加分。蓝本在统一候选池做资格过滤；无合格候选抛 PotionPolicyUnsatisfiedException。不得自造“钉住这瓶补搜→null”通道。
41. 持久化键必须是 (slot, potionId)。同 ID 两瓶药水换槽喝一瓶不算满足 Force；Smart 要“删覆盖”而不是存一条 SMART，否则换药后旧槽语义残留。
42. 持久化严格照蓝本：全局 PotionPolicy 是 JsonIgnore、每次新设置默认 Smart；只保存每槽 directives。配置校验失败按蓝本显式报错，不自造“坏配置全回 Smart”。
43. 【删除本地 policyRevision】策略修改按蓝本走 slot+ID 校验、部署中拒绝、保存、清 ContinuationSource/PendingBaseline，自动计算开启才 Manual 重搜；不得另造代际协议。
44. 一次搜索要跑好几秒，中途改策略会让“已排队步骤”和“新策略”互相矛盾。所以自动部署/执行中直接拒绝修改，并且判断要在控制器里，不能只把控件变灰。
45. 执行喝药要按 (slot, potionId) 精确匹配，找不到就判计划失效。只按名字找会喝错格，“我锁了这瓶它喝了那瓶”是最难解释的一类 bug。
46. Smart 档在当前成本公式下普通战斗基本不喝药（买不回 9 血就拒）。这是蓝本口径，不是 bug；要“该喝就喝”必须改全局档位，不要偷偷把成本公式调松。
47. 全局 Disabled 只决定未登记槽的默认 directive；显式 Force 仍可展开并进入最终资格评估。不得自造“全局 Disabled 压过 Force”的硬上限（蓝本 PotionStrategySnapshot.cs:66-87）。
