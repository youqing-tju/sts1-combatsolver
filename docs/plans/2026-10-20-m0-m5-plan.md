# 执行计划（M0–M5）

> 每个里程碑 = 一组可独立验收的任务；**未过验收不进下一里程碑**。
> 每轮迭代流程见 `2026-10-20-design.md` §7：设计 → 确认 → TDD → 双评审 → commit。

---

## M0 · 骨架与构建链

**目标**：空 mod 能在游戏里加载，弹出最小面板，日志落到文件。

| # | 任务 | 验收 |
|---|---|---|
| M0-1 | `tools/sync-libs.ps1` + `tools/build.ps1` + `-Smoke` | 命令返回 0，`build/` 出 jar |
| M0-2 | `SolverMod` 入口（`@SpireInitializer`）+ `ModTheSpire.json` | 游戏 mod 列表出现 `STS1 Combat Solver` |
| M0-3 | `diag/Trace`：结构化日志到 `mods/../solver-logs/` | 进战斗后日志有记录 |
| M0-4 | `ui/SolverPanel` 最小版：一个可拖动底板 + 一行文字 + 一个按钮 | 面板可见、可点、不挡操作 |
| M0-5 | `@SpirePatch` 钩住 `AbstractDungeon` 战斗开始，打印一次根状态摘要 | 日志出现 `hp/energy/hand size/monster count` |

**停止条件**：若 M0-4 在 Windows 下无法稳定渲染/响应点击 → 降级为外部 HUD（HTTP + 浏览器），记录 ADR 后继续。

## M1 · Mirror 与等价性台架

**目标**：克隆出来的状态与真机**逐字段一致**。

| # | 任务 | 验收 |
|---|---|---|
| M1-1 | `FieldRegistry`：扫描并生成需要克隆的字段清单（不手写） | 清单落盘，覆盖 7 组状态域 |
| M1-2 | `Cloner`：`makeCopy()` → 反射 → 特例 三级策略 | 单帧克隆成功，无异常 |
| M1-3 | `CloneVerifier`：克隆前后全字段 diff | **200 帧 diff = 0（A1）** |
| M1-4 | `Sandbox`：换入/换出 + `effectList` 哑化 + 音效静音 | 沙箱执行后实机状态不变 |
| M1-5 | `ActionDriver`：`actionManager.update()` 跑到静止 | 一次 `Strike` 后状态正确推进 |
| M1-6 | 动作等价台架：随机合法动作序列 vs 真机 | **一致率 100%（A2）** |
| M1-7 | 单节点耗时基准 | 记录基线（目标 ≤ 5 ms） |

**风险点**：字段漏拷导致的静默失真。对策 = M1-3/M1-6 必须全绿，不许"先跑起来再说"。

## M2 · 搜索内核

**目标**：单回合能给出比规则基线更好的出牌顺序；随后扩到跨回合。

| # | 任务 | 验收 |
|---|---|---|
| M2-1 | `ActionGen`：手牌 × 目标 + 药水 + 结束回合 + 选择类分支 | 枚举数量与手算一致 |
| M2-2 | 状态指纹 + 转置表去重 | 重复状态命中率有统计输出 |
| M2-3 | `Beam`：宽度/深度/节点/时间四参数 | 单回合搜索出路线 |
| M2-4 | `eval/RouteScore` 六维排序 | 排序结果可解释（打印各项分值） |
| M2-5 | 跨回合：已知牌序 + `aiRng` 分叉敌方意图 | 跨 3 回合路线可复现 |
| M2-6 | 分片调度：每帧 N ms | 搜索期间帧率 ≥ 50 fps |
| M2-7 | **信息口径 A/B**（若 D8 选"开关"） | 固定种子 20 场，战损差异 + t 值 |

**验收**：120 s 预算内 ≥ 10 万节点（A4 的一半）；20 场固定种子战损 ≤ 规则基线（A3）。

## M3 · 全 Ironclad 覆盖审计

**目标**：把"跑真代码就免费全覆盖"从**假设**变成**证据**。

| # | 任务 | 验收 |
|---|---|---|
| M3-1 | 卡牌扫描器：75 张 × 升级态，逐张在沙箱执行并比对 | 逐张出报告 |
| M3-2 | 怪物扫描器：Act 1–4 全遭遇，跑满 10 回合 | 逐遭遇出报告 |
| M3-3 | 遗物扫描器：逐个触发一次 | 逐遗物出报告 |
| M3-4 | 药水扫描器 | 逐药水出报告 |
| M3-5 | 特殊机制立案：Searing Blow / Snecko Eye / Frozen Eye / Runic Pyramid | 逐项结论 |
| M3-6 | 失败项汇总 + 白名单裁定（D9） | 名单定稿 |

## M4 · 交互与全自动

| # | 任务 | 验收 |
|---|---|---|
| M4-1 | 路线面板完整版（按回合分组、战损、进度条） | 视觉验收 |
| M4-2 | `Executor`：执行本回合（原生动画） | 实机执行正确 |
| M4-3 | `StateStamp` 偏离检测 + 自动重算 | 人为扰动后能重算 |
| M4-4 | 全自动模式（连续搜索→执行→结束回合） | **连续 20 场无异常（A5）** |
| M4-5 | 设置页：预算档位、infoMode、并行度 | 配置生效并持久化 |
| M4-6 | 打包发布：jar + 安装说明 | 干净机器可装 |

**完成即"项目成型"** → 转 public + MIT + 推送 GitHub。

## 时间与顺序约束

- M1 是全项目**唯一的高风险关口**：等价性不过，后面全部无意义 → 不给 M1 设时间上限
- M2-7（信息口径 A/B）依赖 D8 拍板，可与 M3 并行
- M4-6 前不做任何公开宣传；仓库保持 private
