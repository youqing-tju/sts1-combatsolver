## 3. 架构

```
真机战斗 ──捕获──▶ RootSnapshot ──clone──▶ 沙箱状态池
                       │                      │
                       │              Beam 展开（主线程分片）
                       │                      │
                       ▼                      ▼
                 CloneVerifier         路线 = 动作序列 + 预计战损
                       │                      │
                       └──── 状态戳校验 ───────┴──▶ Overlay 展示
                                                     │
                                          执行本回合 / 全自动（原生入口回放）
```

| 模块 | 职责 | 关键类 |
|---|---|---|
| `mirror/` | 根状态捕获、字段级深拷贝、指纹 | `RootSnapshot` `Cloner` `FieldRegistry` |
| `sandbox/` | 全局引用换入换出、副作用屏蔽、动作队列跑到静止 | `Sandbox` `EffectMute` `ActionDriver` |
| `search/` | 动作生成、Beam、去重、预算闸、分片 | `ActionGen` `Beam` `Transposition` `Budget` |
| `eval/` | 六维排序：战损 → 药水成本 → 成长 → 回合 → 消耗 → 结束 | `RouteScore` |
| `exec/` | 计划回放、状态戳、偏离重算 | `Executor` `StateStamp` |
| `ui/` | libGDX 覆盖层：路线面板、进度、三按钮、设置 | `SolverPanel` |
| `api/` | 战前预测（本期仅定义） | `CombatForecastApi` |
| `diag/` | 结构化日志、帧快照落盘、问题包 | `Trace` |
| `bootstrap/` | ModTheSpire 入口、配置、生命周期 | `SolverMod` |

## 4. 机制设计（含举例）

### 4.1 Mirror + 沙箱：一次 `Bash` 的完整走位

**场景**：A0，玩家 72/80 HP、能量 3/3；手牌 `Strike / Strike / Defend / Defend / Bash`；敌人 Jaw Worm 44/44，意图 Chomp 11。

| 步 | 动作 | 细节 |
|---|---|---|
| 1 | **捕获** | 读 `AbstractDungeon.player`（hp/energy/powers/hand/draw/discard/exhaust）、`monsters`（HP/意图/能力/`moveHistory`）、`cardRandomRng.counter=17`、`actionManager` 51 个字段 |
| 2 | **克隆** | 卡牌用 `card.makeCopy()`（游戏自带，保留升级态与临时修正）；RNG 用 `rng.copy()`（seed + counter 一起）；其余对象走反射逐字段，字段清单由扫描器生成 |
| 3 | **换入** | `AbstractDungeon.player/monsters/actionManager` 指向克隆体；`effectList` 指向空列表；`SoundMaster` 哑掉；存档写禁用 |
| 4 | **执行真代码** | `new Bash().use(clonePlayer, cloneMonster)` —— 游戏自己算 8 点伤害、施加 2 层易伤、扣 2 能量、把后续动作压入队列 |
| 5 | **跑到静止** | 循环 `actionManager.update()` 直到队列空 → 新状态：敌 36 HP、易伤 2、能量 1、手牌 4 张 |
| 6 | **还原** | 全局引用原样换回，真机毫发无损 |
| 7 | **入库** | 计算规范化指纹 → 转置表比对 → 进入下一层展开 |

**为什么这是关键**：如果自己重写 `Bash`，要同时处理易伤层数、力量修正、`Strength`/`Weak` 交互、20+ 遗物触发（如 `Paper Phrog` 提升易伤效果、`Vajra` 加力量）、能力牌加成、`Artifact` 抵消。跑真代码 = **0 行规则代码**。

**为什么不走影子模拟**：300+ 卡牌 × 升级态 × 遗物交互是组合爆炸，且每加一个遗物就要回归全部卡牌。Mirror 把这些成本一次性消掉，代价转移到"克隆完整度"——而克隆完整度**可以自动化验证**（见 §6 A1/A2），影子模拟的正确性只能靠人肉核对。

**为什么不走外部进程（CommunicationMod + JSON）**：JSON 只暴露牌面与可见状态，**不给 RNG 内部状态、不给洗牌种子、不给牌堆内部顺序**，无法做逐节点确定性推进；且一次 stdin/stdout 往返是毫秒级，Beam 需要十万级节点。

### 4.2 动作生成与 Beam：为什么不能穷举

同一场景，单回合合法动作 ≈ 7 个（5 张牌 + 药水 + 结束回合），但**顺序自由**：

- 3 点能量打 3 张 1 费牌 → 从 5 张里取 3 张再排列 = `5P3 = 60`
- 混入 2 费 `Bash` 的组合 → 单回合叶子 **100+**
- 跨 8 回合 → `100^8 ≈ 10^16`

⇒ 必须靠 **Beam 宽度 + 状态指纹去重 + 三重预算闸（时间/节点/内存）**。CombatSolver 的经验值可直接沿用：低 60 s/6 万节点 → 极高 300 s/50 万节点。

### 4.3 信息口径：全知 vs 严格信息集（**待你拍板**）

继续上面那场战斗，把牌堆改成**洗牌后剩 9 张**（构成：5 `Strike` + 4 `Defend`，顺序未知）。

| | 全知口径 | 严格信息集 |
|---|---|---|
| 抽牌堆 | 读到实际顺序 `[Strike, Strike, Defend, Defend, Strike, Defend, Strike, Defend, Strike]` | 只知道"5 张 Strike + 4 张 Defend" |
| T2 能抽到什么 | **确定**：3 Strike + 2 Defend | **不确定**：可能是 2 Strike + 3 Defend |
| T1 该不该打 `Bash` | 可精确算出：T2 有 3 张 Strike × 9（含易伤）= 27 伤害，压过 Jaw Worm 的 11 | 只能算期望：`E[伤害] = 27 × P(3攻) + 18 × P(2攻) + 9 × P(1攻)` |
| 搜索成本 | 1 条世界 | **K 个世界并行**（K=4~8），总预算 ÷ K |
| 路线强度 | 更强、战损预估更准 | 更"公平"，同预算下更弱、方差更大 |

**取舍的实质**：真机上 `combat_state.draw_pile` **本来就是有序的**，全知并不需要作弊——只是使用了人类玩家看不到的信息。若目标是"最强自动爬塔"，选全知；若目标是"和人类同信息量的研究基线"，选信息集。

**建议**：默认全知，但把 `infoMode` 做成开关（`OMNISCIENT` / `SAMPLED(k)`），并在 M2 用固定种子做 A/B 量化红利，而不是现在预设结论。

### 4.4 执行与偏离重算

只执行**当前回合**的计划前缀，逐步通过游戏原生入口（`CardQueueItem` / `UseCardAction`）落地，让动画与音效正常播放。每步前把实机状态与预测快照做 `StateStamp` 比对：一致则继续，偏离则立即中止并重算——对应 CombatSolver 的"路线复用 / 计划外重算"。

### 4.5 UI 与 API

- **Overlay**：按回合分组的路线（出牌 / 目标 / 选牌 / 药水 / 结束回合）、预计整场战损、搜索进度、`重新计算 / 执行本回合 / 全自动`；中文位图字体复用游戏自带资源。
- **设置**：预算档位、`infoMode`、并行度、通知开关。
- **API**：`CombatForecastApi.forecast(deck, relics, potions, hp, encounter, ascension) → {expectedHpLoss, route, confidence}`。实现方式是**在进程内用沙箱跑一场假设战斗**，不需要第二个游戏进程——这是 in-process 架构相对 CombatSolver 的额外红利。

## 6. 验收判据（全部可自动化）

| 编号 | 判据 | 手段 |
|---|---|---|

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 副作用隔离不彻底 | 污染实机、坏档 | 只读保护开关 + 存档自动备份 + 静态字段写白名单 + 沙箱异常即回滚 |
| 主线程卡顿 | 掉帧、体验崩坏 | 分片（每帧 N ms）+ 可中断 + 硬预算 + 掉帧超阈值自动降档 |
| 长尾特殊机制 | 个别卡/遗物算错 | A6 扫描器逐项打勾，失败项单独立案 |
| 克隆字段遗漏 | 静默失真（最难查） | A1/A2 自动化等价性台架，任何字段漏拷必暴露 |
| Windows 下 libGDX 输入 hook | 面板点不动 | M0 先做最小面板验证，不通过退外部 HUD |
