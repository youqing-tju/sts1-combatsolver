# UI 复刻（对标蓝本 `reference/sts2-combatsolver/src/UI/`）

> 目标：把面板从「几行文字」推进到蓝本那种「状态条 + 路线动作条 + 策略面板」。
> **约束**：只动 `ui/` 与 `verify/AutoPilot` 的展示函数，**不碰 search/mirror**；风格保持现状（深色半透明 + STS1 金色描边感）。
> 每刀结束都要：`gradlew test --offline` 全绿 → `gradlew jar --offline` → `tools/install.ps1` → commit + push（`git push origin master`）。

## 现状（2026-10-31）

- `src/main/java/io/github/youqing/sts1solver/ui/SolverPanel.java`（513 行）：自绘面板，`rows()` 返回文本行，`layout()` 按字体算宽高，底部三个按钮（AUTO / budget / auto-start），右上角 build 号。
- `AutoPilot.planSummaryLine()` / `planLines(maxLines)`：面板拿计划数据的入口。`planLines` 已改成 `T1 ▸ ▶Bash · Strike` 形式（`▶` = 下一步，每行最多 6 个动作）。
- 蓝本 UI 有 20+ 文件：`SolverOverlay`（主 overlay）、`SolverActionBar` / `SolverActionPill` / `SolverRouteRow`（动作条）、`SolverHudButton`、`SolverMemoryUsageBar`、`SolverGrowthStrategyPanel` / `SolverPotionStrategyPanel` / `SolverRelicStrategyPanel`（三个策略面板）、`SolverOverlayInputBridge` / `SolverOverlayMotionDriver`（输入与缓动）。
- ⚠️ STS1 是 libGDX（`SpriteBatch` + `BitmapFont`），没有蓝本那套控件体系 —— 只复刻**信息结构**，不照搬控件类。

## 四刀切片

### 第一刀：路线动作条（已落地 70%）
- 已有：按回合分组、`▶` 标记下一步、每回合最多 6 个动作。
- 还差：**当前回合整行高亮**（换颜色即可，`rows()` 里给 `T{cur}` 行不同 Color），以及回合计数不要每次重排就跳。
- 改动点：`AutoPilot.planLines()` + `SolverPanel.rows()` 的着色。

### 第二刀：状态条（顶部）
把现在散在日志里的信息搬上来，一行搞定：
```
A1F14 T3 · hp 36/80 · e3 · 敌 Lagavulin 94 (意图20) · 135+base / 34k / 822ms
```
- 数据来源：`SimState.capture()` 的 act/floor/hp/energy/monsters（**注意**：面板每帧都调，`capture()` 太重 → 用 `CombatCapture` 已有的缓存或 `SolverPanel.onCombatStart(summary)` 里那份）。
- 敌人意图：`SimMonster.intentDmg` / `intentAttack`（`SimState` 已捕获）。
- 搜索形状：`AutoPilot.lastSearchShape()`（已有 `135+base / 26k / 642ms` 格式）。

### 第三刀：策略面板（药水 / 遗物 / 成长）
- 蓝本三个面板各自独立开合；我们做**一个**折叠区即可，按优先级只显示「本场有影响的三行」：
  - 药水：`POTION_GATE` 已经算出 `cost / hp_saved / rejected`（`AutoPilot.gatePotionSpending`），直接显示。
  - 遗物：`Coverage` 里有「未镜像遗物」告警（日志里的 `RELIC 未镜像的遗物`），面板上标出来更重要 —— 它决定对拍数据干不干净。
  - 成长：`Score` 的 `persistentBuffValue` / 玩家 `Strength` 等，显示 2~3 个关键层数即可。
- 验收：不新增每帧分配；面板高度随行数自适应（`layout()` 已支持）。

### 第四刀：交互与手感（可选，时间够再做）
- 点击路线行 = 只执行到该回合（蓝本 `ApplyRoute`）；现在只有 AUTO 开关。
- 拖拽/折叠记忆（面板位置已持久化，见 `SolverConfig`）。

## 验收判据

1. 面板上能直接回答四个问题：**现在什么局面 / 它准备怎么打 / 为什么（分数或形状）/ 数据干不干净（失配数）**。
2. 开 AUTO 打一场 Act1，面板不闪、不挡手牌、不随计划刷新跳动。
3. 全量测试绿（当前 532 条）。
4. 每刀一个 commit，push 到 `origin/master`。

## 已知坑

- 面板 `layoutDirty` 只在文本变化时重排；新增字段记得置脏，否则宽度不更新。
- `BitmapFont` 按 `Settings.scale` 缩放，新增文字要沿用 `font.getData().setScale(...)` 的现有写法（`render()` 里画完要还原）。
- 日志里 `panel layout 820x320 rows=6` 是排查面板错位的第一现场。
