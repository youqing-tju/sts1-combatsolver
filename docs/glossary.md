# 术语表（给非技术读者）

> 本项目的所有英文/技术名词都在这里用大白话解释。**每轮新增术语会补进本表**。
> 看文档时遇到不认识的词，先查这里，再看正文。

## 一、命名约定

| 叫法 | 实际指什么 |
|---|---|
| **sts1-combatsolver** | 本项目：给《杀戮尖塔 1》做的战斗求解器 |
| **sts2-combatsolver** | 本项目的**复刻蓝本**，即 GitHub 上的 `Torch1230/CombatSolver`（给《杀戮尖塔 2》做的同类工具） |
| **蓝本** | 同上，指 sts2-combatsolver |

## 二、游戏与模组

| 术语 | 大白话 |
|---|---|
| **Mod（模组）** | 玩家给游戏加的插件，不改游戏本体，靠外挂方式增强功能 |
| **ModTheSpire（MTS）** | 杀戮尖塔的「模组加载器」，负责在游戏启动时把各个 Mod 装进去 |
| **BaseMod** | 最基础的 Mod 框架，别的 Mod 大多依赖它 |
| **创意工坊（Workshop）** | Steam 自带的 Mod 商店，订阅后自动下载 |
| **libGDX** | 杀戮尖塔用的游戏引擎（负责画面、输入、音效）。我们的界面要画在它上面 |
| **药水 / 遗物 / 能力（Power）** | 游戏内三种机制：一次性道具 / 永久被动装备 / 战斗中的持续状态（如「力量+2」） |

## 三、核心机制

| 术语 | 大白话 | 在本项目里 |
|---|---|---|
| **战斗求解器** | 不是「学会打牌」，而是「把当前局面所有打法算一遍，挑最省血的」 | 本项目的主体 |
| **Mirror（镜像）** | 照着原件做一份「等效的替身」，让你能在替身上随便试，原件不受影响 | 蓝本的 Mirror 是**方法镜像**：照着游戏原有规则，逐条重写一份等价逻辑 |
| **对象克隆** | 把战场上的每个东西（手牌、怪物、能量…）**整份复制**一份，得到一个和真机一模一样的副本 | 我们的候选路线「乙」 |
| **影子模拟** | 不复制原件，而是**另建一套简化模型**，把规则重写一遍 | 蓝本的路线「甲」 |
| **沙箱** | 一个「隔离的试验场」：在里面怎么折腾都不会影响真实战斗 | 我们把复制出来的战场放进沙箱试打 |
| **Fork（分叉）** | 从一个局面分出多个平行分支，各走各的 | 搜索时每试一种出牌就是一个分支 |
| **根状态 / 快照** | 某一瞬间战场的完整记录（血、能量、手牌、牌堆、敌人意图…） | 每次搜索都从一个「根」出发 |
| **RNG（随机数发生器）** | 游戏里产生「随机」结果的部件。它其实是**伪随机**：给定起点（种子），后面每一步都固定 | 知道它的内部状态，就能精确算出「下次会抽到什么」 |
| **种子 / 计数器** | 随机数的起点 / 已经用掉了多少次 | 杀戮尖塔的随机数对象自带 `copy()`，复制即分叉 |
| **全知口径** | 求解器可以看穿「未来」：知道接下来会抽到什么牌、怪物下一步干什么 | 蓝本就是这种口径（见设计文档 §10） |
| **严格信息集** | 只用人类玩家能看到的信息，未来的牌按概率猜 | 更「公平」，但同预算下更弱 |

## 四、搜索算法

| 术语 | 大白话 |
|---|---|
| **Beam Search（束搜索）** | 一种「只保留最有希望的 N 条路线，其余丢掉」的搜索法。N 叫**束宽**。不保证数学最优，但在预算内能找到很好的解 |
| **节点** | 搜索树上的一个「局面」。展开一个节点 = 试一步棋 |
| **搜索预算** | 给搜索的时间/节点/内存上限，超了就停，返回目前最好的 |
| **转置表** | 一张「这个局面我以前算过」的备忘录，避免重复计算 |
| **状态指纹** | 把整个局面压成一个短字符串（像身份证号），用来判断两个局面是否相同 |
| **启发式 / 估值函数** | 局面「好不好」的打分公式。搜索靠它判断哪条路线更有希望 |
| **Rollout（推演到底）** | 走到某个局面后，用简单策略一路打到战斗结束，用最终结果给这个局面打分 |
| **主线程 / 后台线程** | 主线程 = 游戏自己的那条流水线（画面、输入、逻辑都在这）；后台线程 = 另开的流水线，可以并行算但**不能碰游戏对象** |
| **时间分片** | 把「算 1 秒」切成很多小段，每帧只算 10 毫秒，这样画面不卡 |

## 五、工程与构建

| 术语 | 大白话 |
|---|---|
| **Java / JDK / JRE** | Java 是游戏的开发语言；JDK = 编译器+工具包；JRE = 只负责运行 |
| **javac / jar** | `javac` 把源码编译成机器能跑的字节码；`jar` 把编译结果打成一个压缩包（Mod 就是这种包） |
| **字节码 / class 版本** | 编译产物。杀戮尖塔跑在 Java 8 上，所以产物必须是「52 版」，否则游戏加载不了 |
| **Gradle** | 一个「自动化构建工具」：自动下载依赖、编译、打包、跑测试。**本项目不需要**（已用 JDK 自带的 javac+jar 替代） |
| **Overlay（覆盖层）** | 画在游戏画面之上的一层界面，比如路线面板 |
| **API** | 两段程序之间的「接口约定」，一方按格式问，另一方按格式答 |
| **JSON** | 一种纯文本的数据格式，人和机器都容易读 |
| **diff（差分）** | 逐项对比两份数据，列出不同的地方。`diff = 0` 就是完全一致 |
| **反射** | Java 的一种能力：在运行时「打开对象的抽屉」，把里面的字段一个个读出来或写进去 |
| **静态字段** | 全程序只有一份的全局变量（比如「当前玩家」）。改它会影响所有地方——所以沙箱要小心地换进换出 |
| **CI（持续集成）** | 每次提交代码，服务器自动跑一遍测试，防止改坏 |

## 六、项目内部编号

| 编号 | 含义 |
|---|---|
| **A1–A6** | 验收判据编号（A = Acceptance）。每条都是可自动验证的硬指标 |
| **M0–M5** | 里程碑编号。M0 是搭骨架，M4 是能全自动打，M5 是留接口 |
| **D1–D9** | 待决策事项编号（D = Decision）。D8 = 信息口径，D9 = 覆盖审计的及格线 |
| **覆盖矩阵** | 一张「哪些卡/怪/遗物/药水已经验证过」的清单，一项一行，逐项打勾。不是数学矩阵 |

## 七、后期（模型阶段）

| 术语 | 大白话 |
|---|---|
| **行为克隆 / 模仿学习** | 让神经网络模仿求解器的决策：看局面 → 输出「该出哪张牌」 |
| **强化学习（RL）** | 让程序自己反复试错，按输赢给奖励，慢慢学会打 |
| **教师数据** | 由强求解器产出的「标准答案」，用来训练较小的模型 |
| **蒸馏** | 把大而慢的求解器的本事，压缩进小而快的模型里 |
